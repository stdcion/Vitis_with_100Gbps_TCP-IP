# ppclient — измеритель RTT для hls_pp_dual_krnl

Шлёт сообщения на плату и меряет, за сколько вернулось эхо.

## Почему Go

Разработка на macOS, запуск на Windows у платы. Go кросс-компилируется одной
командой и даёт статический бинарник — на машине с платой не нужны ни Go, ни
runtime, ни DLL. Копируется один `.exe`.

Методика (калибровка часов, персентили, `TCP_NODELAY`, сверка вне
измеряемого интервала) перенесена из
`host/hls_pingpong_krnl/pingpong_client.c`, где отрабатывалась на C.

## Сборка

```sh
./build.sh
```

Даёт `bin/ppclient.exe` (Windows), `bin/ppclient-linux`, `bin/ppclient-macos`.
Скрипт сначала гоняет `gofmt -l` и `go vet` — при ошибках не собирает.

## Запуск

```
ppclient.exe -host 192.168.10.10 -port 7001 -bytes 64 -count 100000 -csv rtt.csv
```

| флаг | по умолчанию | что делает |
|---|---|---|
| `-host` | — | IP платы, обязателен |
| `-port` | 7001 | TCP-порт (`basePort` в ядре) |
| `-bytes` | 64 | размер сообщения, 1..4096 |
| `-count` | 10000 | сколько измерять |
| `-warmup` | 1000 | прогрев, в статистику не идёт |
| `-verify` | нет | сверять каждое эхо (шумит: см. ниже) |
| `-csv` | — | файл сырых сэмплов |
| `-timeout` | 5s | на соединение и на каждое чтение |

## Что читать в выводе

Вывод намеренно короткий — числа без пояснений, пояснения здесь.

```
timer: gran 41ns, overhead 41ns, 26% zero-diffs (darwin)
192.168.10.10:7001: 64 bytes x 10000 (+1000 warmup)

10000 samples, 64 bytes
min        :     38000 ns  ( 38.000 us)
p50        :     54500 ns  ( 54.500 us)
...
one-way    ~ 27.250 us (p50/2, if symmetric)
```

**Строка `timer`** — собственная погрешность измерителя, до всяких измерений.
`zero-diffs` показывает, годится ли таймер: доля пар вызовов `time.Now()` с
нулевой разницей. Близко к 100% — часы не различают соседние моменты и
микросекунды мерить нечем; программа тогда печатает `WARNING`. На Windows
ожидается ~100 нс гранулярности (`QueryPerformanceCounter`), это ~3%
погрешности при RTT 3 мкс.

**`min` и `p50`** — то, что сравнивать с бюджетом задержки. `p99`/`p99.9`
шумнее, чем у C-версии: в Go нет привязки к ядру CPU без cgo, поэтому хвосты
содержат планировщик Windows, а не только сеть.

**`*** N MISMATCHES`** — единственная строка, которая кричит. Эхо не совпало
с отправленным: дефект ядра (`keep` последнего слова, границы `payload[]`,
`txLength` в `pp_echo`), и измерение при этом бессмысленно.

**Что входит в RTT:** сисколлы Write/Read, драйвер и сама NIC, провод, CMAC,
стек TOE в обе стороны, ядро `pp_echo`. **Чего не видно:** сколько из этого
ядро, а сколько стек — для разбивки нужна врезка времени на `axis_net`,
отдельная работа.

## Отказы

| вывод | что значит |
|---|---|
| `connect ...: connection refused` | порт на плате не открыт → `portState` = 0 или 1 |
| `connect ...: i/o timeout` | SYN ушёл, ответа нет — то же молчание, что было у `dual_echo` |
| `connect ...: no route to host` | ARP не разрешился: адреса, линк |
| `no echo after 0 msgs` | соединение есть, ядро молчит → читайте `ppState` |
| `no echo after N msgs` | встало на N-м сообщении → `ppState` назовёт шаг |

Значения `ppState`, которые вернёт `pp_dual_dump`:

| | шаг | что не случилось |
|---|---|---|
| 0 | NOTIFY | уведомление до ядра не дошло |
| 1 | META | `read_pkg` отправлен, `rx_meta` не пришла |
| 2 | RX | слова идут, `tlast` не пришёл |
| 3 | REQ | не пишется `tx_meta` (транзитное состояние, видеть не должны) |
| 4 | STATUS | стек не ответил на `tx_meta` — **TX-путь достигнут** |
| 5 | TX | слова не принимаются, backpressure |

## Ограничения

- **Один запрос за раз** (ping-pong), иначе RTT не измерить. Пропускную
  способность этим не мерить — ядро тоже обрабатывает по одному сообщению.
- **4096 байт максимум** — предел `PP_MAX_WORDS*64` в ядре. Больше ядро
  усечёт.
- **`-verify` добавляет шум.** Сравнение больших сообщений вытесняет данные
  из кэша и портит СЛЕДУЮЩИЙ сэмпл. По умолчанию сверяется только прогрев —
  этого хватает, чтобы поймать испорченное эхо.
- **Нет разбивки RTT.** Видно суммарное время; сколько из него ядро, а
  сколько стек — не видно. Для этого нужна врезка времени на `axis_net`,
  это отдельная работа.
- **Нет `--cpu`/`--rt`** как в C-версии: `runtime.LockOSThread()` привязывает
  горутину к потоку, но не к ядру CPU.

## Порядок измерения у платы

**Клиент сам по себе ничего не поднимает.** До него плату надо
сконфигурировать по JTAG: задать IP/MAC обоим стекам, записать `basePort` и
стартовать ядро. Без этого порт не открыт и клиент получит
`connection refused`.

```sh
# 1. ПЛАТА (Vivado, JTAG): поднять оба стека и ядро.
#    Адреса по умолчанию: 192.168.10.10 (половина a, кабель здесь)
#                         192.168.10.20 (половина b, без кабеля)
vivado -mode batch -source scripts/vivado/jtag_ctrl.tcl -tclargs pp_dual_bringup

#    Другие адреса -- аргументами, в hex и БЕЗ точек:
#      -tclargs pp_dual_bringup c0a80a0a 02aa00000001 c0a80a14 02bb00000002 7001
#    Смотрите в выводе portState: должен стать 2. Если 0 или 1 -- порт не
#    открылся, дальше идти незачем.

# 2. ХОСТ: захват. Запустить ДО отправки -- это единственный источник
#    правды, не зависящий от нашей телеметрии.
#    Windows: Wireshark на QSFP-интерфейс, фильтр  tcp.port == 7001
#    Linux:   sudo tcpdump -i <iface> -ttt -w pp.pcap 'tcp port 7001'

# 3. ХОСТ: сначала дым-тест на 100 сообщений
ppclient.exe -host 192.168.10.10 -port 7001 -count 100

# 4. ХОСТ: если эхо пришло -- настоящее измерение
ppclient.exe -host 192.168.10.10 -port 7001 -bytes 64 -count 100000 -csv rtt.csv

# 5. ПЛАТА: счётчики
vivado -mode batch -source scripts/vivado/jtag_ctrl.tcl -tclargs pp_dual_dump
```

Порядок важен: шаг 1 обязателен, шаг 2 до шага 3, и `-count 100` перед
сотней тысяч — иначе при отказе потратите время впустую.

## Клиент НЕ читает регистры ядра

`portState`, `ppState`, `notifyCount` живут в `s_axi_control` и доступны
только по JTAG (`pp_dual_dump`) — либо по PCIe через XRT, которого в этой
сборке нет. Клиент ходит по сети через QSFP, а туда регистры не выведены.

Поэтому при отказе клиент печатает **подсказку** с таблицей значений
`ppState` — чтобы не вспоминать их в этот момент, — но само число надо
взять на плате.
