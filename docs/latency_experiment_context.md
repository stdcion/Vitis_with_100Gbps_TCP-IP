Файл для передачи в новый диалог. Описывает, где мы остановились, что уже

Дата: 2026-08-07. Последний коммит: `951f382 echo latency test (jtag)`.
Рабочее дерево чистое — всё описанное ниже закоммичено.

---

## Зачем всё это

Цель — **боевой OUCH-гейтвей**: `n клиентов → FPGA (серверный сокет) → мукс →
FPGA (клиентский сокет) → биржа`, и обратно. На обоих концах TCP, внутри
SoupBIN + OUCH.

Каждое сообщение проходит TCP-стек **дважды**: приём с одного порта, передача в
другой. Сколько это стоит по времени — неизвестно, а без этого числа нельзя
оценить бюджет гейтвея. Текущая задача: **измерить пол** — задержку стека без
логики гейтвея.

Схема эксперимента: оба QSFP закольцованы кабелем «сам на себя». Клиентский
сокет на порту 0 шлёт пакет, серверный на порту 1 отвечает тем же пакетом в то
же TCP-соединение (эхо). Всё внутри FPGA на одном `ap_clk` — поэтому таймстемпы
сопоставимы напрямую, без синхронизации часов.

Визуальная схема тракта с точками измерения:
`docs/Тракт измерения задержки — dual-QSFP U200 (8_7_2026 6：14：02 PM).html`

Пошаговая инструкция для работы на плате (Windows + Vivado, JTAG):
`docs/latency_experiment_windows.md` — в стиле `docs/bringup_dual_windows.md`,
со схемой стенда, ожидаемым выводом каждой команды и разбором отказов.

### Порядок работы на плате

Подробно, с ожидаемым выводом и разбором отказов —
`docs/latency_experiment_windows.md`. Коротко:

```tcl
source C:/jtag_ctrl.tcl
echo_bringup_dual 0a01d498 000a35029de5 0a01d499 000a35029de6
epd_calibrate                    ; # сколько стоит JTAG-транзакция
epd_configure 0a01d499 7001 64
epd_enable 1
epd_status                       ; # соединение открылось?
epd_measure                      ; # один замер + проверка баланса
epd_collect 20                   ; # статистика
```

Свипы потом: `epd_configure ... 128`, `... 256`, до 1500 — **без пересборки**,
для этого параметры и вынесены в `s_axi_control`. Потолок `msgBytes` — **4096**
байт (`EPD_MAX_WORDS = 64` слов по 64 байта), выше ядро молча обрежет.

**Проверка линка здесь не через `ping`.** Кабель идёт QSFP0 ↔ QSFP1, порты
соединены друг с другом, а не с PC — `ping` с PC не пойдёт и не должен (это
отличие от `bringup_dual_windows.md`, где кабели шли в сетевые карты). Физику
проверяем по `stat_rx_aligned` / `stat_rx_status` в `hw_vio_1` и `hw_vio_2`,
должны быть единицы на обоих. Плюс: FEC с обеих сторон наш, несовпадения быть
не может.

Требование к адресам жёстче, чем при проверке линка: **оба IP в одной подсети
/24** (в стеке `IP_DEFAULT_GATEWAY = 0`, маршрутизации нет) и **последние
октеты обязаны различаться** (индекс ARP-таблицы, см. ниже).

### Что будет дальше

**Врезки на `axis_net_*`** — чтобы отделить время стека от времени CMAC.
Сейчас доступны только четыре точки на портах ядра, они дают суммарное
`NET_FWD`/`NET_REV` (стек + CMAC + кабель). Разложение требует прозрачного
пробника, врезанного в шину между `cmac_krnl` и `network_krnl`.

**Спроектировано, не собрано** — [latency_net_probe_design.md](latency_net_probe_design.md).
Коротко: врезка живёт в HDL-обёртке probe-ядра (там уже есть счётчик тактов и
регистры, читаемые по JTAG — второй счётчик заводить нельзя, это та самая
ошибка с расхождением шкал), `axis_net_*` идёт через обёртку сквозным проходом,
мимо HLS-ядра. Четыре новых таймстемпа раскладывают круг на семь слагаемых
вместо трёх. Главная нерешённая трудность — на `axis_net_*` идёт весь трафик
(ARP, ACK, retransmit), и наш кадр там ничем не выделен; проверка достоверности
захвата — `STACK_TX + WIRE_FWD + STACK_RX == NET_FWD`.

**Замер под нагрузкой** — сейчас режим «один пакет в тракте» по триггеру. Для
хвоста распределения понадобится поток и `seq_id` в payload для сопоставления
таймстемпов.

## Как измеряется

Четыре точки, все на портах самого ядра (доступны даром, врезки не нужны):

```
t1' = tx_data_a  запрос уходит в стек порта 0
t2' = rx_data_b  запрос пришёл из стека порта 1 (в эхо)
t1  = tx_data_b  ответ уходит в стек порта 1
t2  = rx_data_a  ответ пришёл из стека порта 0 (в измеритель)
```

Ядро отдаёт **сырые** значения, интервалы считает PC:

```
RTT     = t2  − t1'     весь круг
NET_FWD = t2' − t1'     запрос: стек 0 tx + CMAC + кабель + CMAC + стек 1 rx
ECHO    = t1  − t2'     эхо внутри ядра (ожидается единицы тактов)
NET_REV = t2  − t1      ответ, то же в обратную сторону
```

**Проверка:** `NET_FWD + ECHO + NET_REV = RTT`. `epd_measure` считает её сам,
но **это алгебраическое тождество**, а не признак хорошего замера: сумма
сворачивается в `t2 − t1'` при любых четырёх числах. Разойтись она может только
если регистр прочитан в момент обновления (`TORN READ`). Ни смешения пакетов, ни
сдвига шкал между половинами она не поймает — от первого защищает режим одного
пакета по триггеру, от второго то, что шкала физически одна (см. ниже).

Такт `ap_clk` = 6.061 нс (165 МГц) — это разрешение измерения. Было 5.882
(170 МГц) до 11.08.2026, частоту снизили из-за тайминга.

Все четыре точки берутся из **одного** счётчика: его держит HDL-обёртка ядра и
раздаёт обеим половинам проводом. `NET_FWD` и `NET_REV` вычитают точки разных
половин, поэтому на двух раздельных счётчиках любое их расхождение завысило бы
одно ровно настолько, насколько занизило другое — не задев ни `RTT`, ни `ECHO`,
ни проверку баланса.

### Почему сырые значения, а не агрегаты в ядре

Сначала я сделал `min`/`max`/`sum` в ядре — это было ошибкой по четырём
причинам, и одна из них серьёзная:

**64-битные суммы нельзя корректно прочитать.** `s_axi_control` отдаёт 32 бита
за транзакцию, значит 64-битный регистр читается двумя обращениями, а между
ними ядро успевает обновить значение. При переносе через границу 2^32 получился
бы мусор — редко и невоспроизводимо. Все регистры теперь 32-битные.

Плюс: гибкость (любой интервал считается на PC), отладка (по сырым видно, что
сломалось), место и тайминг.

### Почему триггер, а не поток

Цикл замера — 6 JTAG-транзакций:

```
write triggerGo   → снимает sampleReady и отправляет пакет
poll  sampleReady → ждём, пока круг замкнётся
read  4 регистра  → сырые таймстемпы, гонки нет
```

Согласованность бесплатно: пока хост не дёрнул триггер, новый пакет физически
не появится, значит четвёрку можно читать спокойно. Не нужны ни номер набора,
ни теневые регистры.

Запись `triggerGo` одновременно снимает `sampleReady` — они всегда идут парой,
и это экономит транзакцию. «Сброс при чтении» в HLS невозможен: `s_axilite` не
даёт ядру узнать, что регистр прочитали.

## Найденные и исправленные ошибки

Стоит знать, потому что часть из них легко внести заново.

### Баг в `jtag_ctrl.tcl`, который сломал бы первый же запуск

`expr {0x$ip_str}` **не подставляет переменную** внутри фигурных скобок —
падает с `invalid bareword "x"`. Было в трёх местах, включая `network_configure`
и `axi_read32`.

То есть `echo_bringup_dual` упал бы на первой строке, не записав ни одного
регистра: ни IP, ни MAC, ни `ap_start`. Стек не запустился бы, ping не пошёл, и
причину искали бы в прошивке, которая исправна.

Исправлено на `scan`:

```tcl
scan $ip_str  %x   ip
scan $mac_str %llx mac      ← %llx, иначе 48-битный MAC обрезался бы
```

### Скаляры между стадиями DATAFLOW

Сначала передавал `freeCounter`, `connected`, таймстемпы между стадиями по
ссылке. В регионе `DATAFLOW` так нельзя: стадии становятся независимыми
процессами, связь должна идти через `hls::stream`. **csim этого не поймал бы** —
там обычный C++; ошибка вылезла бы только на csynth.

Переделано: каждая стадия держит свой счётчик тактов (стартуют вместе от одного
сброса, поэтому шкалы синхронны), таймстемпы идут парами через FIFO. Пары
важны: клиент пишет `(t1', t2)` вместе, эхо — `(t2', t1)` вместе, поэтому
измеритель не может сложить точки разных пакетов.

Подтверждение, что исправлено верно: **II=1 на всех пяти стадиях** в csynth.

### Ограничение ARP-таблицы стека

`arp_server_subnet.cpp`: `arpTable[256]`, индексируется **одним** октетом:

```cpp
arpTable[query_ip(31,24)]
```

Адреса внутри стека лежат **LSB-first** (автор пишет это прямо в
`network_stack.sv:38`, и `IP_SUBNET_MASK = 32'h00FFFFFF` там же — это /24
перевёрнутая). Значит `(31,24)` — **последний** октет IP.

Для нашей пары `10.1.212.152` / `.153` индексы 152 и 153 различаются, коллизии
нет. Но для боевого гейтвея: **у клиентов должны различаться последние октеты
IP**, иначе вторая ARP-запись затрёт первую. Плюс маска /24 зашита параметром, а
`IP_DEFAULT_GATEWAY = 0` — все участники обязаны быть в одной подсети.

Записано в комментарии ядра.

## Чего проверки НЕ покрывают

Честные границы, чтобы не переоценить готовность:

**csim не видит дедлок по FIFO.** `hls::stream` там неограничен, `full()` всегда
false. Нужен cosim или железо. Cosim в `run_csim.tcl` выключен, и там написано
почему: на родственных ядрах он не проходит из-за скалярных портов `s_axilite`
при `ap_ctrl_none`, а у нас их 16.

**Модель стека в тестбенче — реконструкция.** Написана по коду
`hls_pingpong_krnl`, а не по самому `network_krnl`. В частности **ARP в csim не
участвует вообще** — модель доставляет пакеты напрямую. На плате открытие
соединения пойдёт через ARP-резолв, которого тест не видит.

Проверить это отдельно, до измерения, нечем: `ping` в loopback-схеме недоступен
(порты соединены друг с другом, а не с PC). Поэтому ARP-резолв первый раз
проверяется самим экспериментом, и симптом его отказа —
`epd_status` с растущим `попыток соединения` при нулевом `отправлено`. Отличить
«ARP не разрешился» от «линка нет» помогает `stat_rx_aligned` в VIO: при живом
линке и неоткрывающемся соединении в первую очередь смотреть адреса (одна
подсеть /24, разные последние октеты).

**Заглушки Vivado в тесте `jtag_ctrl.tcl` проверяют арифметику, не транспорт.**
`create_hw_axi_txn` / `run_hw_axi` заменены пустышками. Реальный JTAG, наличие
`hw_axi_1` и ответы устройства — только на плате.

**Не проверено на живой плате вообще ничего.** Ни dual_echo, ни это ядро.

## Открытые вопросы

**Цена JTAG-транзакции неизвестна.** Мои оценки «единицы миллисекунд» были
догадкой; правдоподобный диапазон 0.5–20 мс зависит от того, доминирует ли
Tcl-обвязка Vivado. Отсюда и `epd_calibrate` в скрипте — измерить, а не гадать.
Заодно там видна оптимизация: `axi_write32`/`axi_read32` создают транзакцию
заново каждый вызов (`create_hw_axi_txn` после `delete`), можно создать однажды
и переиспользовать.

**FEC.** В наших ядрах RS-FEC выключен (параметр не задан, остаётся дефолт IP).
Официальный OpenNIC для этой платы, наоборот, включает `INCLUDE_RS_FEC {1}`.
Настройка обязана совпадать с обеих сторон линка. В loopback обе стороны наши,
так что совпадает; но если подключать к чему-то внешнему — проверить.

**SLR1 занят на 92% по CLB** (45532 из 49260) при LUT всего 48%. Оба
`network_krnl` сидят там. Для текущего дизайна проходит, но боевой гейтвей с
реальной логикой мукса встанет в тот же SLR — про это стоит думать до того, как
логика написана.

```bash

T=$(mktemp -d)/tree

cd $T/kernel/user_krnl/k/src/hls && g++ -std=c++14 -I$SHIM -o /tmp/tb $K.cpp tb/test_$K.cpp && /tmp/tb
```

```bash
cd kernel/user_krnl/hls_echo_probe_dual_krnl/src/hls && vitis_hls -f run_csim.tcl
```

```bash
make -f Makefile.vivado report USER_KRNL=hls_echo_probe_dual_krnl BOARD=u200
```
