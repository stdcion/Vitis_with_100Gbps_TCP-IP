# Загрузка и проверка на Alveo U200 (Windows + Vivado, JTAG)

Инструкция для echo-ядра (`hls_echo_krnl`). Порт **7001** захардкожен в ядре,
настраивать его не нужно.

Прошивается только конфигурация FPGA. **Flash не трогаем** — заводская
прошивка платы остаётся на месте. После выключения питания плата вернётся к ней.

## Что нужно

| Файл               | Куда положить         |
|--------------------|-----------------------|
| `tcp_listener.bit` | `C:\tcp_listener.bit` |
| `jtag_ctrl.tcl`    | `C:\jtag_ctrl.tcl`    |

Ещё понадобится:

- USB-кабель JTAG к плате (micro-USB на планке U200),
- QSFP0 (**ВЕРХНЯЯ** клетка — так в UG1289) соединён с сетевой картой PC — DAC-кабелем или
  двумя трансиверами через оптику,
- IP и MAC, которые присвоим плате.

## 1. Подключиться к плате

Vivado → **Open Hardware Manager** (на экране Flow Navigator слева, либо
`Flow → Open Hardware Manager`).

Дальше **Open Target → Auto Connect**.

В панели Hardware должно появиться дерево:

```
localhost (1)
  xilinx_tcf/Xilinx/<серийник>
    xcu200_0 (0)
```

Если устройства нет — проверить USB-кабель и что плата запитана (U200 требует
дополнительное питание PCIe, не только слот).

## 2. Загрузить битстрим

Правый клик по `xcu200_0` → **Program Device**.

В диалоге:

- **Bitstream file**: `C:\tcp_listener.bit`
- **Debug probes file**: оставить пустым

**Program**. Занимает ~30–60 секунд.

По завершении дерево устройства перестроится, и под `xcu200_0` появятся
отладочные ядра:

```
xcu200_0 (4)
  hw_axi_1        ← JTAG-to-AXI master, через него всё управление
  hw_ila_1        ← ILA на CMAC
  hw_vio_1        ← VIO внутри network_krnl
  MIG_1           ← состояние калибровки DDR4
```

**`hw_axi_1` обязателен.** Если его нет — скрипт работать не будет: он ищет
AXI-мастера через `get_hw_axis`.

## 3. Проверить калибровку DDR4

Двойной клик по `MIG_1` в панели Hardware. Откроется вкладка с таблицей стадий
калибровки. Нужно, чтобы все стадии были пройдены (`PASS` / зелёные).

Либо в Tcl Console:

```tcl
get_property STATUS.CAL_STATUS [get_hw_migs]
```

Если калибровка не прошла — дальше идти бессмысленно, TCP-стек хранит таблицы
сессий в DDR4 и без памяти работать не будет.

## 4. Загрузить скрипт управления

В Tcl Console (внизу окна Vivado):

```tcl
source C:/jtag_ctrl.tcl
```

Слеши **прямые**, даже на Windows — Tcl трактует `\` как escape.

Скрипт ничего не делает при загрузке, только объявляет процедуры. Молчание —
нормальный результат.

## 5. Настроить сеть и запустить стек

Три команды, **строго в этом порядке**:

```tcl
network_configure 0a01d498 000a35029de5
network_set_buffers
network_start
```

Аргументы `network_configure` — IP и MAC в hex, без префикса `0x` и без
разделителей:

| Что | Пример                               | Как получить                                    |
|-----|--------------------------------------|-------------------------------------------------|
| IP  | `10.1.212.152` → `0a01d498`          | каждый октет в hex: 10=0a, 1=01, 212=d4, 152=98 |
| MAC | `00:0a:35:02:9d:e5` → `000a35029de5` | убрать двоеточия                                |

IP выбрать в той же подсети, что у сетевой карты PC. MAC — любой, лишь бы
уникальный в сегменте; локально администрируемый (второй бит первого октета = 1,
например `02:00:00:00:00:01`) гарантированно ни с чем не столкнётся.

### Что должно напечататься

```
network_krnl: ip=0x0a01d498 mac=0x000a35029de5
  прочитано:  ip=0x0a01d498 mac=0x000a35029de5
  запись подтверждена
network_krnl: axi00_ptr0=0x00000000 axi01_ptr0=0x40000000
network_krnl: ap_ctrl=0x01 (ap_start=1 ap_done=0)
```

**`запись подтверждена`** — ключевая строка. Скрипт читает регистры обратно; если
её нет, JTAG-мастер не достучался до `s_axi_control`, и всё дальнейшее
бессмысленно. Причины: не загружен этот битстрим, или `hw_axi_1` отсутствует.

Порядок команд не переставлять: IP и MAC защёлкиваются внутри стека по фронту
`ap_start`, поэтому `network_configure` обязана идти до `network_start`.
Подробности — в комментариях `jtag_ctrl.tcl`.

## 6. Проверка с PC

С машины, подключённой к QSFP0:

```
ping 10.1.212.152
```

ARP отвечает сам TCP-стек на плате. Если ping идёт — поднялся 100G-линк,
работает ARP, IP прописался. Это уже подтверждает, что дизайн живой.

Дальше — TCP:

```
ncat 10.1.212.152 7001
```

(или `telnet 10.1.212.152 7001`, или PowerShell:
`Test-NetConnection 10.1.212.152 -Port 7001`)

**Соединение установилось = TCP работает.** Ответа не будет: echo-ядро только
принимает и сбрасывает данные, обратно ничего не отправляет. Сам факт
установления соединения и есть результат.

## Если не работает

**Ping не идёт** — смотреть линк CMAC. Двойной клик по `hw_vio_1`, добавить
пробы: там выведены `stat_rx_status`, `stat_rx_aligned` и счётчики стека.
Если `rx_aligned = 0` — линк не поднялся: проверить, что кабель в **QSFP0**
(ВЕРХНЯЯ клетка, см. UG1289; QSFP1 в этом дизайне не разведён), и что вторая сторона тоже
настроена на 100G без FEC.

**Ping идёт, TCP не подключается** — стек живой, проблема в порту или в
user-ядре. Проверить, что порт в `hls_echo_krnl.cpp` (`#define LISTEN_PORT`)
совпадает с тем, куда подключаешься.

**После перезагрузки платы всё пропало** — так и задумано, конфигурация
волатильная. Повторить шаги 2–5.

## Повторная загрузка

Программировать заново можно сколько угодно, `Program Device` перезаписывает
конфигурацию. После каждой перепрошивки — заново шаги 4–5 (`source` и три
команды): регистры сбрасываются вместе с логикой.
